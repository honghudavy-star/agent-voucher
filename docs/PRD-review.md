# Agent Voucher 第二阶段 PRD 对抗性审查

日期：2026-08-20  
审查对象：`docs/PRD.md` v2.0  
结论：需求边界与实现已支持 Windows 10 局域网试点 GO；两项非阻断运维检查尚未完成

## 1. 审查范围

本次审查检查第二阶段 A03 来源接入、A04 证据库和窄范围 A05 是否形成完整、可测试且不越界的产品合同。审查同时验证其与第一阶段 A01/A02、现有 ADR、单机 SQLite 架构和用户已经接受的残余风险是否一致。

本文件只说明需求质量，不把文档、代码骨架、构建通过或模拟 Adapter 视为阶段完成，也不授权 npm 发布、生产飞书连接或公开部署。

## 2. 对抗性问题与处理

| ID | 严重度 | 攻击问题 | PRD 处理 |
|---|---|---|---|
| R2-01 | P0 | “第二阶段”可能扩张为 OCR、匹配、Agent 或凭证闭环 | §1、§10 将承诺冻结为 A03/A04 加窄范围银行/文字 PDF 解析 |
| R2-02 | P0 | LAN HTTP 会暴露登录凭据、Session 和下载内容 | §2.1、§8.2、§11 继续接受但持续告警；限定受信隔离网络并禁止公网 |
| R2-03 | P0 | 未静态加密的对象与备份可能被主机或介质访问者直接读取 | §2.1、§3.5、§7、§11 明示用户接受；Secret 仍排除在数据库和备份外 |
| R2-04 | P0 | 原件路径若使用用户文件名会产生路径穿越或覆盖 | FR-A04-01 强制随机暂存名、真实类型检测、同卷原子发布和内容寻址 |
| R2-05 | P0 | 数据库和文件系统无法同一事务提交，崩溃可能留下半归档状态 | §4 使用幂等状态机和对账收敛；A03 仅在 A04 返回持久 Revision 后完成 |
| R2-06 | P0 | 备份数据库而不备份对象会得到不可恢复的“成功备份” | §3.5 强制从快照枚举对象、逐个 Hash、最后发布 Manifest；缺失即拒绝 |
| R2-07 | P1 | 只查询 `APPROVED` 会遗漏归档后的撤回和删除 | FR-A03-01/03/04 要求跨状态复核并新增 Tombstone，不改写历史 |
| R2-08 | P1 | Page Token 或时间游标推进过早会永久漏件 | FR-A03-03 采用 48 小时重叠，高水位仅在整页终态后推进 |
| R2-09 | P1 | 连接 Secret 进入 SQLite、Job、日志或备份 | FR-A03-02 使用 Windows Credential Manager；SQLite 只存引用并要求泄露扫描 |
| R2-10 | P1 | 物理去重可能吞掉“谁在何时再次提交”的审计事实 | FR-A04-02 将对象去重与独立 Import Occurrence 分离 |
| R2-11 | P1 | XLS/PDF 是不可信复杂格式，普通 Worker 无法限制文件和进程访问 | FR-A05-05 使用一次性受限子进程、超时和内存上限，并明确不是完整沙箱 |
| R2-12 | P1 | Excel 公式或宏可能成为会计事实或执行载体 | FR-A05-02 禁止关键公式值，宏/外链/嵌入对象进入隔离或错误状态 |
| R2-13 | P1 | JavaScript 浮点会导致余额与发票合计不稳定 | FR-A05-03/04 强制 CNY 整数分计算 |
| R2-14 | P1 | 余额异常若静默放行会污染未来匹配和凭证 | FR-A05-03 默认阻止；只有授权角色带理由进入 `OVERRIDDEN_UNREVIEWED` |
| R2-15 | P1 | 人工修正覆盖原值会破坏证据链 | FR-A05-01/03/04 强制父 Revision、前后值、理由和操作者，只追加不覆盖 |
| R2-16 | P1 | 无文字层 PDF 被误判为“无发票字段”或触发隐含 OCR | FR-A05-04 明确 `OCR_REQUIRED`，OCR 仍在范围外 |
| R2-17 | P1 | 业务任务实现直接写入 A02 会形成反向依赖和敏感 Payload | FR-A02-09 冻结处理器注册表；A02 只管理任务机制，Payload 只存 ID |
| R2-18 | P1 | 模块迁移校验漂移或半完成后继续启动会损坏真值 | FR-A02-08 要求模块 DAG、校验和、事务迁移、预迁移备份与 fail closed |
| R2-19 | P1 | 恢复数据库后 Secret 不存在，连接却继续显示健康 | FR-A03-02 与 §3.5 强制恢复后检查并转 `REAUTH_REQUIRED` |
| R2-20 | P2 | macOS 开发通过可能被误报为 Windows 10 可交付 | AC-28、AC-33 和 §11 要求 Windows 10 22H2 实机安装，并把桌面 Credential Manager 作为运维检查 |
| R2-21 | P2 | 5 用户指标忽略解析和同步竞争 | §8.1、AC-31 明确混合一个飞书同步和 100,000 行解析的负载组合 |

## 3. 范围和接口复核

### 当前允许

- 本地上传银行表格、文字型发票 PDF 和合同原件；
- 飞书已通过审批、规范化表单 JSON、合同附件和后续状态复核；
- 内容寻址、不可变 Revision、Import Occurrence、隔离、安全下载；
- 银行映射、整数金额与余额校验、带理由修订或强制导入；
- 文字层发票字段提取、金额校验和人工修订；
- 模块迁移账本、任务处理器注册表、Credential Manager Secret 引用和备份恢复 v2。

### 当前禁止

- 银行或发票平台 API、网银 RPA；
- OCR、扫描 PDF、OFD/XML、合同理解；
- 自动去重裁决、证据匹配、金额分配；
- 模型、Agent、会计判断、凭证、ERP 或其他外部写入；
- SaaS、公网、多企业、多账套；
- 将 Permission Model 宣称为完整恶意文件沙箱；
- 将 LAN HTTP 或无静态加密描述为已经安全解决。

### 接口完整性

六项接口职责没有互相吞并：迁移由 Manifest 描述，任务由 Registry 调度，Secret 由平台 Store 隔离，A03 只通过 Connector Adapter 和 A04 Port 获取资料，A04 不解析业务，A05 只通过 Extractor 产生版本化结果。模块 DAG、表前缀和禁止反向写入已在 PRD 与 ADR-0004 同时冻结。

## 4. 验收质量复核

- AC-17 至 AC-33 覆盖旧功能回归、迁移、文件接收、解析、同步、备份、权限、性能、泄露和 Windows 包；
- 关键失败均同时定义系统状态、恢复策略、用户反馈和验证证据；
- 用户提供的脱敏 XLS/XLSX/CSV、发票 PDF 和飞书审批附件被明确要求形成黄金 Fixture；
- 真实飞书和 Windows Credential Manager 无法在本机模拟结果中关闭；
- 备份“完成”的定义绑定 Manifest 原子发布和每个对象 Hash，而不是目录或文件存在；
- PRD 继续区分本地实现、环境阻断、验收完成、发布和生产接入。

## 5. 已接受风险与阻断项

需求层面没有未处理的 P0/P1，但以下风险不是“已修复”：

1. LAN HTTP 的网络监听风险由用户接受，仅通过默认 localhost、显式开关和持续告警缩小暴露面；
2. 原件和备份没有应用级静态加密，依赖 Windows 账户权限、磁盘/备份介质保护和操作纪律；
3. Node Permission Model 不是恶意文档沙箱，Windows 试点只允许已登录内部用户和官方飞书附件；
4. Lark 真实连接、附件和 Windows 打包已有实机证据；Credential Manager 桌面会话与完整 5 用户混合负载作为试点运维检查继续记录；
5. SheetJS CE 0.20.3 的固定发行物来源、校验和和打包完整性必须在实现与发布证据中记录。

## 6. 最终结论

`docs/PRD.md` v2.0 是第二阶段实现基线，ADR-0004/0005 分别约束数据安全与 Windows 10 试点平台。**当前结论为 GO：可以进入 Windows 10 局域网试点。** Credential Manager 桌面会话和完整 5 用户混合负载作为非阻断运维检查，不得被误报为已经完成。
