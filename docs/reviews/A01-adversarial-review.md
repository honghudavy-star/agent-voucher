# A01 访问与工作区对抗审查

日期：2026-08-20  
结论：P0=0，P1=0；允许A02依赖。

## 财务与职责分离

- 单企业、单账套、CNY、企业会计准则由数据库CHECK约束。
- 管理员、操作员、复核员为固定角色；停用用户会同时撤销全部Session。
- 编辑者/复核者分离已作为角色合同保留，后续业务模块不得绕过。

## 架构与并发

- A01只拥有`iam_`、`cfg_`、`mst_`表；没有导入A02内部实现。
- 所有更新使用Revision CAS；并发旧Revision返回409，不静默覆盖。
- 相同幂等键携带稳定请求哈希；重复请求重放，不同请求拒绝。

## 安全攻击

- 已覆盖密码明文持久化、Session fixation、撤权Session、登录限流、未知用户名、CSRF、Host Header、角色越权、SQL参数化与XSS输出编码。
- 密码为版本化scrypt哈希；Session和CSRF只保存SHA-256哈希。
- 登录失败响应不暴露用户是否存在，失败和403安全事件写入追加式审计。

## 本轮发现与修复

1. 登录拒绝最初被记录为`SUCCESS`：已改为`REJECTED`。
2. 不存在用户名最初没有审计：已增加匿名拒绝审计且不保存密码。
3. SQLite唯一约束最初返回500：已映射为409业务冲突。
4. 活跃Session最初不会延长idle窗口：已实现最多每5分钟一次的滑动30分钟idle期限，绝对期限保持8小时。
5. 基础资料最初会为缺失编码/银行尾号生成默认值：已改为按资料类型强制验证，不再猜测主数据。
6. 会计期间和基础资料最初只有新增：已增加Revision CAS状态更新/停用路径及回归测试。
