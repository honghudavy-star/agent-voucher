# Agent Voucher 产品需求文档：第二阶段来源与证据

版本：2.0  
日期：2026-08-20  
状态：Phase 2 Windows 10 LAN pilot GO；Credential Manager 桌面会话与完整五用户混合负载保留为非阻断运维检查  
产品名：Agent Voucher  
包名与 Slug：`agent-voucher`

## 1. 文档定位

本文件是当前仓库的正式产品需求基线。第一阶段基线覆盖 A01“访问与工作区”和 A02“运行与审计”；第二阶段在不破坏这些边界的前提下交付 A03“来源接入”、A04“证据库”，并提前实现 A05 中严格受限的银行表格解析和文字型发票 PDF 提取。

第二阶段的产品承诺是“资料可进入、原件可追溯、结构化结果可人工修订并可恢复”，不是自动做账闭环。OCR、匹配、Agent、凭证草稿、ERP、付款、审核、过账和报税均不属于本阶段。

## 2. 产品目标与成功标准

### 2.1 目标用户与部署

- 中国境内单一法人、单账套、人民币记账的小型财务团队；
- 最多 5 名登录用户，角色为 `ADMIN`、`OPERATOR`、`REVIEWER`；
- 正式试点主机为 Windows 10 22H2，运行时固定 Node.js 24；
- 单主机、单应用实例、单数据目录；默认只监听 `127.0.0.1`；
- `--lan` 继续使用用户明确接受的未加密 HTTP，只允许受信、隔离的私有网络；
- 原件和备份暂不做应用级静态加密，这是明确接受而非已经消除的风险。

### 2.2 第二阶段目标

1. 从本地上传和飞书已通过审批接收银行、发票、合同资料；
2. 以内容寻址方式保存不可变原件、独立导入发生记录和来源链；
3. 解析 CSV/XLS/XLSX 银行流水并校验余额；
4. 从具有有效文字层的 PDF 发票提取开票字段；
5. 让授权用户通过新 Revision 修订解析结果，不覆盖原始事实；
6. 将数据库、Graph 状态和全部被引用证据对象作为一个可验证世代备份和恢复；
7. 在失败、重试、撤回、重复和恢复后缺 Secret 时给出可审计的确定状态。

### 2.3 成功标准

- 每次合法上传或飞书归档均能追溯至来源、Import Occurrence、Evidence Revision 和内容 SHA-256；
- 相同内容只保存一份物理对象，但不同导入行为各自留痕；
- 银行解析全程以整数分处理 CNY，余额异常默认阻止提交；
- 发票每个字段保留原始文本、页码、位置、解析器版本与校验结果；
- 飞书分页、重试、Token 失效和审批撤回均可恢复或进入明确终态；
- 备份缺少任何被引用对象、数据库不完整或 Manifest 未发布时不得恢复；
- A01/A02 权限、审计、单 Writer、Doctor 和恢复边界不退化；
- 第二阶段自动化、Windows 10 与真实样本证据已支持局域网试点 GO；Credential Manager 桌面会话和完整五用户混合负载未完成，不得误报为已验收。

## 3. 范围

### 3.1 A03 来源接入

#### FR-A03-01 来源类型

- 本地上传支持：银行 `XLS`、`XLSX`、`CSV`；发票 `PDF`；合同 `PDF`、`DOCX`、`JPG`、`PNG`；
- 飞书只接入企业自建应用的审批实例、规范化表单 JSON 和审批附件；
- 飞书发现查询只接收 `APPROVED` 实例；已归档实例仍需复核后续 `CANCELED`、`REVERTED` 或删除状态；
- 合同在本阶段只归档，不解析内容或条款。

#### FR-A03-02 飞书连接配置

- `ADMIN` 配置 App ID、Secret 引用、审批定义 Code 白名单、合同附件控件映射、首次回溯日期和每日同步时间；
- 默认每天按主机本地时间 02:00 同步，支持 `ADMIN` 和 `OPERATOR` 手动同步；
- 主机错过计划时间时，启动后只补跑一次，不为每个遗漏周期重复排队；
- App Secret 必须存 Windows Credential Manager；SQLite 只保存不可反推出 Secret 的 `secret_ref`；
- Secret 不进入任务 Payload、日志、审计、Graph、备份或错误响应；
- 恢复数据库后若 Credential Manager 不存在相应 Secret，连接进入 `REAUTH_REQUIRED`。

#### FR-A03-03 同步、游标与幂等

- 发现窗口使用已完成时间高水位加 48 小时重叠，防止延迟可见和边界遗漏；
- 单次运行可保存当前 Page Token 以便重试，但持久高水位只能在整页条目全部成为终态后推进；
- 每个远端实例以外部 ID 定位，以状态、表单、时间线和附件 Code 的规范 Hash 计算远端 Revision；
- A03 只有收到 A04 已持久化的 Evidence Revision ID 后，才能把条目标为 `ARCHIVED`；
- 附件全部归档或明确标记终态失败前，实例不得标记完整成功；
- 同一外部 ID、远端 Revision 和附件重放不得制造重复物理对象或丢失导入记录。

#### FR-A03-04 状态与失败处理

状态至少包含：

```text
DISCOVERED → FETCHING → ARCHIVED | PARTIAL | REAUTH_REQUIRED | FAILED
```

- 401/403 转为 `REAUTH_REQUIRED`，停止依赖该连接的新同步；
- 429 遵守 `Retry-After`；5xx 和网络超时按有限次数重试；
- 禁用连接时取消尚未运行的相关任务，正在归档的对象完成当前原子步骤后终止；
- 已归档实例后续撤回或删除时新增 Tombstone，不删除或改写历史 Evidence；
- 每个错误必须有稳定、脱敏的错误码和可执行的用户说明。

### 3.2 A04 证据库

#### FR-A04-01 流式接收与上限

- Web 上传使用流式 multipart，不在 Web 进程内存中保存完整文件；
- 最大文件 50 MiB；超过上限时删除残缺临时文件，只保存隔离元数据；
- 使用随机暂存名，原始文件名不得参与服务器路径解析；
- 上传期间计算 SHA-256、实际大小并检测真实类型；扩展名、声明 MIME 和实际类型不一致时隔离；
- 暂存与正式对象位于同一文件系统，校验成功后原子发布。

#### FR-A04-02 内容寻址与不可变性

- 正式对象按 SHA-256 分层寻址，相同内容只保存一份物理对象；
- 每次本地上传或远端归档均创建独立 Import Occurrence，记录操作者、时间、来源、原文件名和结果；
- Evidence Revision 只追加，保存对象 Hash、来源链、业务类型、父 Revision 和 Tombstone；
- 本阶段不对合法正式对象执行垃圾回收，任何解析或用户修订均不得覆盖原件；
- 状态至少包含 `STAGING`、`STORED`、`PHYSICAL_DUPLICATE`、`QUARANTINED`。

#### FR-A04-03 隔离与下载

- 隔离区使用与正式对象不同的命名空间；除超限残片外，隔离文件保留 7 天；
- `ADMIN` 可提前清理隔离文件，必须二次确认并写审计；到期清理由后台任务执行；
- 下载必须鉴权，响应使用强制附件、`X-Content-Type-Options: nosniff` 和安全文件名；
- 产品不在浏览器内执行 Office 宏、PDF 脚本、外部链接或嵌入对象；
- 磁盘满、连接中断或 Hash 校验失败时，正式 Evidence 不可见，暂存残片应尽力清理。

#### FR-A04-04 跨模块接入接口

`EvidenceIngestPort` 必须支持本地流或 `CanonicalEvidenceEnvelope` 的幂等接收，并返回 Evidence Revision ID、Import Occurrence ID、对象 Hash 和最终状态。调用方不得直接写 `evd_` 表或内容目录。

### 3.3 窄范围 A05 结构化提取

#### FR-A05-01 通用规则

- `StructuredExtractor` 支持预览和完整解析，并返回带解析器版本、配置 Hash 和错误码的版本化结果；
- 状态至少包含 `QUEUED`、`PARSED`、`VALIDATED`、`NEEDS_REVIEW`、`OVERRIDDEN_UNREVIEWED`、`FAILED`；
- 解析只读取单个 Evidence 对象；解析结果和人工修订只追加 Revision；
- 每次修订保存来源行/字段、原值、新值、理由、操作者、时间和父 Revision；
- 重复只提示，不自动删除流水或裁决是否为同一交易。

#### FR-A05-02 银行字段映射

必填目标字段为交易日期、金额和流水余额。金额可选择单列收支金额，或借方/贷方双列。可选字段为交易号、币种、对方名称、对方账号、摘要和账户尾号。

- 用户选择工作表、表头行、数据起始行、源顺序、CSV 编码和分隔符；
- CSV 至少支持 UTF-8 和 GB18030；
- Mapping Revision 保存表头指纹和字段配置；相同表头只能自动建议，不能自动导入；
- 预览必须显示首部、尾部和全部错误样本；
- 公式单元格不得直接作为交易日期、金额或余额；宏、外部链接、压缩炸弹、超大共享字符串和嵌入对象必须隔离或返回稳定错误；
- 单次文件最多 100,000 条数据行。

#### FR-A05-03 金额与余额校验

- CNY 金额统一以整数分保存和计算，禁止 JavaScript 浮点金额参与会计校验；
- 按源文件顺序验证相邻余额和本行收支；正序、倒序语义由 Mapping 明确；
- 首个余额错误和其后受影响行在 UI 中以文字、图标和红色加粗共同表达；
- 缺失必填余额或余额异常默认禁止提交；
- `ADMIN` 或 `OPERATOR` 可填写非空理由强制导入，批次状态为 `OVERRIDDEN_UNREVIEWED`；
- 授权用户可新增、修改或软删除解析行；每次操作生成新 Revision 并重算整批余额。

#### FR-A05-04 发票文字层提取

从文字型 PDF 提取：发票代码、发票号码、开票日期、销售方名称与税号、购买方名称与税号、不含税金额、税额、价税合计和币种。

- 每个字段保存原始文本、页码、文本项位置、解析器版本、歧义和校验错误；
- 使用整数分校验“不含税金额 + 税额 = 价税合计”；
- 无有效文字层返回 `OCR_REQUIRED`；文字不完整返回 `PARTIAL_TEXT`；未知版式返回 `UNSUPPORTED_LAYOUT`；
- 密码保护、文件损坏、页数超限分别返回稳定错误码；PDF 最多 500 页；
- 人工修订必须填写理由并创建新 Revision；
- 不做 OCR、发票真伪、电子签名或税务状态验证。

#### FR-A05-05 解析进程边界

- XLS/XLSX 和 PDF 解析使用一次性子进程，不以普通 Worker Thread 作为安全边界；
- 子进程只接收单个临时只读文件路径和解析配置，不接收数据库路径、飞书 Token 或其他 Evidence 路径；
- 清空业务环境变量，并使用 Node.js 24 Permission Model 只开放所需文件和运行资源；禁止写文件、再派生子进程、Worker 和原生扩展；
- 单次解析上限为 60 秒和 256 MiB；超时、OOM 或异常退出由父进程终止并记录稳定错误码；
- Permission Model 只是纵深防御，不得宣称为恶意文件的完整沙箱。

### 3.4 A02 平台扩展

#### FR-A02-08 模块迁移

- 保留现有迁移历史，新增模块迁移账本；
- `MigrationManifest` 包含模块、版本、依赖、校验和和升级 SQL；
- 启动时验证模块 DAG、校验和和数据库版本；未知新版、校验和漂移或未完成迁移必须 fail closed；
- 迁移前创建现有格式的数据库备份，迁移 SQL 在事务中执行；
- 表所有权为：A01 `iam_`/`cfg_`/`mst_`，A02 `job_`/`prc_`/`aud_`/`ops_`，A03 `conn_`/`src_`，A04 `evd_`，窄范围 A05 `doc_`。

#### FR-A02-09 任务处理器注册表

- A02 只提供排队、租约、心跳、取消、重试和审计，不导入业务模块；
- A03–A05 在组合根通过 `JobHandlerRegistry` 注册任务 Schema、队列类别、重试分类和结果脱敏规则；
- 网络任务和解析任务各最多并发 1 个，二者可以并行；SQLite 仍保持一个 Writer；
- Job Payload 只保存 ID 和小型参数，不保存审批正文、银行行、发票正文、Page Token 或 Secret；
- 未注册任务、Schema 不符或连接已禁用时必须拒绝或取消，不得静默执行。

### 3.5 备份与恢复 v2

- 先生成 `app.db` 快照，再从快照枚举所有历史 Evidence Revision 和 Tombstone 引用的对象 Hash；
- 复制并逐个校验全部引用对象后生成 `graph.db` 快照；
- 最后原子发布带格式版本、Generation ID、数据库 Hash 和对象清单的 Manifest；Manifest 发布前的目录一律视为失败备份；
- 隔离文件和 Credential Manager Secret 不进入备份；备份介质可直接读取财务原件，UI 和文档必须持续提示；
- 恢复先在新目录验证 Manifest、Schema、数据库完整性、Graph 可用性和每个 Evidence Hash；
- 验证通过后在同一文件系统执行目录交换，任一步失败回滚并保留恢复前副本；
- 恢复后重新检查 Secret 引用，缺失连接转为 `REAUTH_REQUIRED`；
- 正式 Evidence 本阶段不删除，因此备份复制期间不引入对象 GC 竞争。

## 4. 稳定内部接口与依赖方向

第二阶段冻结以下内部能力契约，具体 TypeScript 形状由实现保持版本化和可测试：

| 接口 | 所有者 | 最小职责 |
|---|---|---|
| `MigrationManifest` | A02/组合根 | 声明模块迁移、依赖、校验和、升级 SQL |
| `JobHandlerRegistry` | A02 | 注册任务 Schema、租约类别、重试和脱敏策略 |
| `SecretStore` | 平台适配层 | 保存、读取、删除 Secret；业务库只持有引用 |
| `ConnectorAdapter` | A03 | 测试连接、分页发现、取实例、下载附件、禁用连接 |
| `EvidenceIngestPort` | A04 | 幂等接收流或规范 Envelope 并返回持久化身份 |
| `StructuredExtractor` | A05 | 预览或解析一个 Evidence 并返回版本化结果 |

模块依赖固定为 `A03 → A04 → A05`；A05 不能反向修改来源或 Evidence，A04 不理解飞书业务字段，A03 不直接读取内容目录。跨模块流程使用状态机、幂等键和可重放命令，不构造跨数据库/文件系统的伪分布式事务。完整决策与数据流见 [ADR-0004](adr/0004-phase2-source-evidence-threat-model.md)。

## 5. Web 工作台与权限

### 5.1 页面

- 资料来源：飞书连接、权限检查、审批白名单、附件映射和同步计划；
- 资料导入：银行、发票、合同本地上传；
- 银行映射：工作表、表头、字段、顺序、编码、预览和错误统计；
- 银行流水：有效 Revision、余额状态、重复提示、增删改和强制导入理由；
- 发票详情：提取字段、来源位置、错误和人工修订；
- 证据库：来源、Hash、Revision、远端状态和安全下载；
- 同步记录：分页进度、部分失败、重试和重新认证；
- 隔离区：原因、剩余保留时间和提前清理。

### 5.2 权限矩阵

| 能力 | ADMIN | OPERATOR | REVIEWER |
|---|---:|---:|---:|
| 查看来源、Evidence、解析结果和同步记录 | 是 | 是 | 是 |
| 配置、测试或禁用飞书连接 | 是 | 否 | 否 |
| 保存共享 Mapping | 是 | 否 | 否 |
| 本地上传、手动同步、运行解析 | 是 | 是 | 否 |
| 修订银行行或发票字段 | 是 | 是 | 否 |
| 带理由强制导入余额异常批次 | 是 | 是 | 否 |
| 下载原件 | 是 | 是 | 是 |
| 提前清理隔离文件 | 是 | 否 | 否 |

所有写操作必须验证 Session、CSRF、角色和当前 Revision；并发冲突返回 409，不得覆盖较新 Revision。任何未列出的写操作默认拒绝。原有 A01/A02 权限继续有效。

## 6. 关键用户流程

### UF-07 本地资料导入

用户选择资料类型和文件；系统流式暂存、Hash、类型校验并创建 Import Occurrence。合法文件原子进入证据库；重复内容指向已有对象但保留本次发生记录；异常文件进入隔离并显示原因。

### UF-08 银行映射与导入

用户选择 Mapping 参数并查看首尾与错误样本。系统在受限子进程解析，以整数分校验余额。正常批次提交为 `VALIDATED`；异常批次默认阻止，授权用户可填写理由强制提交。后续增删改生成新 Revision 并重新校验。

### UF-09 发票提取与修订

用户上传文字型 PDF；系统在受限子进程提取字段并展示字段来源。无文字层明确提示需要未来 OCR，不伪造结果。授权用户可填写理由修订，原值始终可查。

### UF-10 飞书同步

管理员配置连接并测试权限。计划任务或手动任务重叠回查已通过审批，逐一把规范表单和附件归档到 A04。分页只有在整页条目终态后推进；历史实例撤回时新增 Tombstone。认证失效时要求重新授权，不丢弃已有 Evidence。

### UF-11 备份恢复

管理员创建 v2 备份；系统在 Manifest 发布前验证数据库和每个对象。恢复必须在应用停止时由本机 CLI 明确确认，先在新目录完成全量验证，再原子交换并保留恢复前副本。重启后运行 Doctor，并提示补齐缺失飞书 Secret。

## 7. 数据、隐私与保留

| 数据类别 | 存储 | 保留与删除 |
|---|---|---|
| 来源配置与同步游标 | `app.db` 的 `conn_`/`src_` | 禁用不等于删除；不保存 Secret 明文 |
| Secret | Windows Credential Manager | 由管理员删除；不备份 |
| 正式原件 | 内容寻址对象目录 | 本阶段永久保留，不做 GC |
| Evidence 与 Import Occurrence | `app.db` 的 `evd_` | 只追加 Revision 和 Tombstone |
| 结构化结果与 Mapping | `app.db` 的 `doc_` | 只追加 Revision；业务行软删除 |
| 隔离文件 | 独立隔离目录 | 默认 7 天；超限残片立即清理；管理员可提前清理 |
| 任务、Graph、审计 | `app.db`/`graph.db` | 不得包含原件正文、解析全文、Page Token 或 Secret |
| v2 备份 | 用户选择的本地目录 | 用户负责介质保护和保留；无应用级加密 |

不发送遥测。飞书 API 是本阶段唯一业务网络出口；银行和发票均为本地文件接收，不访问银行、税务或发票平台。

## 8. 非功能要求

### 8.1 性能与容量

- 最大单文件 50 MiB、银行 100,000 行、PDF 500 页；
- 解析最长 60 秒、子进程内存上限 256 MiB；
- 5 个登录会话、一个飞书同步和一个 100,000 行银行解析并发时，普通读取 p95 小于 500 ms、短写 p95 小于 1 秒；
- 无未处理 SQLite 锁错误，写队列达到上限时快速拒绝。

### 8.2 安全

- 正式平台 Windows 10 22H2、Node.js 24；启动、测试和安装必须拒绝不支持的 Node 主版本；
- 解析进程采用最小文件权限、无业务 Secret、有限时间和内存；
- 未登录用户不能上传、同步、下载或解析；
- 日志、任务、Graph、审计、错误和备份 Manifest 不含 App Secret、Tenant Token、银行正文或发票正文；
- LAN HTTP 与无静态加密风险按 ADR-0003/0004 持续明示，不得包装成安全完成。

### 8.3 可靠性与可访问性

- 外部 ID、远端 Revision、内容 Hash 和幂等键共同保证崩溃后安全重放；
- 文件系统和数据库无法同事务提交时，以可恢复状态和对账任务收敛；
- 颜色不是错误或隔离状态的唯一表达；所有核心流程可用键盘完成并支持 200% 缩放；
- 长文件名、长错误信息和大批量列表必须可截断展示并保留可访问的完整值。

## 13. 第一阶段持续生效的基线

第二阶段是增量交付，不替代以下 A01/A02 产品合同：

- 全新数据目录以一次性终端令牌初始化单工作区、单账套和首个 `ADMIN`；令牌只能成功一次；
- 用户名唯一，密码以随机盐 `scrypt` 哈希保存；登录失败不泄露账户存在性，连续 5 次失败锁定 15 分钟；
- Session/CSRF Token 只存 Hash，会话空闲上限 30 分钟、绝对上限 8 小时；所有写请求验证 CSRF；
- `ADMIN` 管理用户、工作区、账套显示名、会计期间及有限主数据；银行账户只保存 2–8 位尾号；
- 配置写入使用 Revision CAS；用户停用撤销活动 Session；任何未列出的写操作默认拒绝；
- `app.db` 是业务与审计真值；一个写 Worker、两个只读 Worker 通过版本化数据库 RPC 访问；
- 成功状态变化与审计在同一 `app.db` 事务提交；审计只追加，错误和 metadata 不含 Secret；
- A02 任务使用有界队列、租约、心跳、有限重试和稳定错误码；第二阶段只扩展处理器，不改变运行时所有权；
- 最小 LangGraph `runtime-smoke` 只用于流程自检，不能调用模型、来源、解析或外部写操作；
- `doctor` 检查数据目录、实例锁、数据库完整性、外键、Schema、PRAGMA 和 Graph；失败时非零退出且不自动修复；
- 单数据目录只允许一个实例，拒绝符号链接、共享网络盘和无法确认陈旧的进程锁；
- CLI 保留 `start`、`doctor`、`backup`、`restore` 和 `completions`；备份/恢复语义由本阶段 v2 扩展。
